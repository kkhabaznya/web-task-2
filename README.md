# Практическая работа №2, вариант №28.

Реализовать HTTP API для выполнения вычислительных задач согласно теме курсовой работы. Для хранения данных на диске в веб-приложении используется файловая система управления базами данных (СУБД). Необходимо обеспечить поддержку управления данными через HTTP API, схема данных представлена в нотации Entity Relationship (ER). 

Для полноценной работы всех исполняемых файлов требуются следующие библиотеки: 
bottle, requests, hypothesis, pytest, coverage

# Файлы с исходным кодом.
> ### main.py
> Набросок для первого этапа. Содержит минимальный функционал, классы для трех существ согласно варианту, автоматическое присваивание uid. Не содержит какого-либо интерфейса для взаимодействия.

> ### app.py
> Веб-приложение с HTTP API согласно варианту.
> #### check_headers
> Перед обработкой запроса, проверяет его валидность, метод должен быть из тех, что были в таблице требований, содержимое строго json, Accept-Language строго ru-RU.
> #### add_client
> POST /rest/api/v2/add-client
> Получает на вход user_agent и создаёт на его основе клиента, автоматически присваивая uid и время создания.
> #### collect_client
> GET /rest/api/v2/collect-client
> Возвращает всех клиентов, или, при условии наличия uid в запросе, возвращает определённого клиента.
> #### revise_client
> PUT /rest/api/v2/revise-client/:uid
> Позволяет изменить user_agent для клиента с определённым uid.
> #### add_message
> POST /rest/api/v2/add-message
> Создаёт клиента на основе входных данных. В случае запуска вне тестового режима, выполняет запрос с использованием main.py
> #### collect_message
> GET /rest/api/v2/collect-message/:client
> Возвращает сообщения на основе uid клиента, при отсутствии указания возвращает всех.
> #### revise_message
> PUT /rest/api/v2/revise-message/:uid
> Изменяет сообщение с определённым uid.
> #### collect_feedback
> GET /rest/api/v2/collect-feedback/:message
> Выводит фидбеки с uid определённого сообщения, без указания такового выводит все.
> #### collect_report
> GET /rest/api/v2/collect-report
> Составляет отчёт, на основе предоставленной формулы.
> #### load_seed_data
> Загружает тестовые данные для заполнения базы данных.

> ### client.py
> Используется для проведения тестов. Все функции выполняют HTTP API запросы к серверу.

> ### test_mbt.py
> Проводит тестирование сервера и его функционала с использованием библиотеки hypothesis. Запускает локальный сервер, и с использованием клиента client.py выполняет запросы к нему. Содержит дополнительные тесты для покрытия кодов ошибок и некоторых исключений.

# Скрипты запуска.
> ### run_server.bat
> Выполняет запуск сервера app.py. В качестве тестовых данных для первичного заполнения базы данных используется содержимое файла data.json

> ### run_server_test.bat
> Выполняет быструю проверку всех обработчиков HTTP API согласно варианту. Требуется запущенный сервер.

> ### run_curl_cli.bat
> Запускает утилиту для удобного создания и отправки запросов на сервер. Требуется запущенный сервер.

> ### run_test_mbt.bat
> Запускает MBT. Создаёт html отчёт по выполненной проверке.

# Пример работы.
Запустите сервер с помощью run_server.bat.
Запустите run_server_test.bat для проверки всех видов запросов.
Или запустите run_curl_cli.bat для создания произвольных запросов с произвольными данными.

Для тестов достаточно просто запустить run_test_mbt.bat, без запуска run_server.bat.
